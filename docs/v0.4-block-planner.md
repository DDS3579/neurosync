# NeuroSync v0.4 Spec: Time-Block Planner

**Status:** Drafted on branch `v0.4` (source of truth for all v0.4 implementation steps)  
**Scope:** Local-first Cal Newport–style time-block planning built on Dexie/IndexedDB, preserving backward compatibility with existing v0.2/v0.3 data and keeping the data boundary calendar-ready for future sync and Google Calendar integration.

---

## 1. Concept & Mental Model

Inspired by time-block planning in Cal Newport's *Deep Work*:

1. **Tasks split into Blocks:** Larger tasks are broken into concrete work chunks (`Block`s), defaulting to `defaultBlockMin` (`50` min) or custom durations.
2. **Block Tray (unscheduled pool):** Unplaced blocks wait in a tray (`status: 'todo'`, without `plannedDate` or `plannedStart`).
3. **Two daily placements:** Each day, the user pulls blocks from the tray into the day in one of two ways:
   - **Onto a timeline slot** (`status: 'scheduled'`, with `plannedDate` and snapped `plannedStart`), or
   - **Into that day's to-do list** without a fixed clock time (`status: 'todo'`, with `plannedDate` set and `plannedStart` unset).
4. **Protect deep work, batch shallow work:** Deep work blocks (`kind: 'deep'`) are protected from fragmentation and tracked against an adjustable soft daily guideline (`deepWorkCapMin`, default `240` min). Shallow tasks (`kind: 'shallow'`) are batched together rather than scattering deep windows. Recovery blocks (`kind: 'recovery'`) reserve intentional breathers and movement.
5. **Rebuild when the day changes:** When commitments shift or time runs over, the remaining open day can be rebuilt deterministically without erasing completed or skipped blocks.
6. **Shutdown ritual:** An explicit end-of-day ritual (`DayPlanMeta.shutdownDone`) closes the day, records an optional reflection, and calmly moves or returns unfinished blocks without guilt or streak pressure.

## 2. Domain Model (`src/types/domain.ts`)

All entities extend `Base` (`id: string`, `createdAt: ISODateTime`, `updatedAt: ISODateTime`).

```ts
export type TaskKind = 'deep' | 'shallow' | 'recovery';
export type TaskStatus = 'inbox' | 'active' | 'done' | 'archived';
export type BlockStatus = 'todo' | 'scheduled' | 'done' | 'skipped';

export interface Project extends Base {
  name: string;
  color?: string;
  archived: boolean;
}

export interface Task extends Base {
  title: string;
  projectId?: string;
  notes?: string;
  kind: TaskKind;
  estimateMin: number;
  dueDate?: ISODate;
  status: TaskStatus;
  /** Weekday numbers 0 (Sunday) through 6 (Saturday), matching Date.getDay(). */
  repeatWeekdays?: number[];
}

export interface Block extends Base {
  taskId: string;
  order: number;
  plannedMin: number;
  status: BlockStatus;
  plannedDate?: ISODate;
  /** 24-hour local 'HH:mm' (validated against /^([01]\d|2[0-3]):[0-5]\d$/). */
  plannedStart?: string;
  actualMin?: number;
  focusSessionId?: string;
  completedAt?: ISODateTime;
}

export interface DayPlanMeta extends Base {
  date: ISODate;
  shutdownDone: boolean;
  reflection?: string;
}
```

### `UserSettings` Additions

- `defaultBlockMin?: number` — default `50` (minutes per generated block)
- `deepWorkCapMin?: number` — default `240` (adjustable soft daily guideline, never a hard lock)
- `snapMin?: number` — default `15` (timeline snap increment in minutes)

### Relationship to Existing `DayPlan` (`dayPlans`)

- Existing `DayPlan` records (Dexie v6, storing per-day `wakeTime`, `sleepTargetMin`, `windDownMin`, and `commitments: PlannerFixedCommitment[]`) remain intact so v0.2/v0.3 backups stay valid and fixed commitments continue to anchor the timeline.
- Per-day sleep/wind-down boundaries and fixed commitments are read alongside `Block` and `DayPlanMeta` for the active date.

## 3. Persistence, Dexie v10 Migration & Backup Plan

- **Dexie `SCHEMA_VERSION = 10`** (`src/lib/db/dexie.ts`):
  - Add tables:
    - `projects: "id, archived"`
    - `tasks: "id, projectId, kind, status, dueDate"`
    - `blocks: "id, taskId, status, plannedDate, [plannedDate+order]"`
    - `dayPlanMeta: "id, date"`
  - Upgrade migration backfills `defaultBlockMin: 50`, `deepWorkCapMin: 240`, `snapMin: 15`, and `schemaVersion: 10` on `settings`.
- **Repositories & Hooks (`src/lib/db/repositories/`, `src/lib/db/hooks.ts`):**
  - UI components never call `getDb()` directly; all reads/writes go through `projectRepository`, `taskRepository`, `blockRepository`, and `dayPlanMetaRepository` (plus Dexie `useLiveQuery` hooks).
- **Backup Compatibility (`src/lib/db/backup.ts`):**
  - Bump backup `SCHEMA_VERSION` to `10`.
  - Add Zod schemas for `projects`, `tasks`, `blocks` (enforcing `plannedStart` requires `plannedDate`), `dayPlanMeta`, and the three optional settings fields.
  - Keep importing `schemaVersion` `1–9` backups cleanly by normalizing missing v10 tables to `[]` and missing planner settings to `{ defaultBlockMin: 50, deepWorkCapMin: 240, snapMin: 15 }`.

## 4. Scheduling Rules & Hard Invariants

All timeline math operates in `[0, 1440)` minute offsets relative to the day's `wakeTime` (reusing `timeToOffset` / `formatOffsetTime` from `plannerEngine.ts`), so midnight-crossing sleep windows work identically to daytime schedules.

1. **15-minute snap grid:** Timeline start times and drag/resize deltas snap to `snapMin` (default `15` minutes).
2. **Sleep & wind-down protection:** Let `sleepStart = 1440 - sleepTargetMin` and `windDownStart = Math.max(0, sleepStart - windDownMin)`. No `scheduled` block may start before `wakeTime` (`offset < 0`) or extend past `windDownStart` (`offset + plannedMin > windDownStart`).
3. **No overlapping blocks:** Two `scheduled` blocks on the same `plannedDate`, or a `scheduled` block and a fixed commitment, cannot overlap (`a.start < b.end && b.start < a.end`). Any invalid drop, edit, or move is rejected with a plain explanation naming the conflicting window or block.
4. **Date/time pairing invariant:** A `Block` with `plannedStart` set and `plannedDate` unset is invalid (`plannedStart` requires `plannedDate`). Moving a block to the Day To-Do list clears `plannedStart` and sets `status: 'todo'`; moving it to the Tray clears both `plannedDate` and `plannedStart` and sets `status: 'todo'`.
5. **Delete & edit consistency:**
   - Deleting a `Task` cascades cleanly to remove its blocks (or blocks not yet converted into independent `FocusSession` logs—historical `FocusSession` records remain untouched).
   - Deleting a `Project` clears `projectId` on associated `Task`s rather than deleting tasks.
   - Editing a block's `plannedMin` or `plannedStart` re-runs overlap and sleep/wind-down validation before persisting.
6. **Soft deep-work cap:** Total `kind === 'deep'` planned minutes exceeding `deepWorkCapMin` (default `240`) surfaces a calm, adjustable advisory note—never a hard block or shaming alert.

## 5. Core Planner Workflows

1. **Task Capture & Block Splitting:**
   - Users create `Task`s (`deep`, `shallow`, or `recovery`) with `estimateMin` and optional `projectId`, `dueDate`, `repeatWeekdays`, and `notes`.
   - Splitting a task generates `Block`s sized up to `defaultBlockMin` (or custom split sizes) with sequential `order` values in the **Block Tray**.
   - **Repeating tasks:** Opening a date checks active tasks matching `repeatWeekdays` and idempotently creates that day's blocks if none exist for `(taskId, date)`.
2. **Tray → Day To-Do vs. Timeline Slot:**
   - Dropping or moving a block onto **Today's To-Do** sets `plannedDate = activeDate`, `plannedStart = undefined`, `status = 'todo'`.
   - Dropping or moving a block onto a **Timeline Slot** sets `plannedDate = activeDate`, snapped `plannedStart`, `status = 'scheduled'` (validated against commitments, existing blocks, wind-down, and sleep).
   - **Shallow batching:** Auto-fill / batch helper groups `shallow` blocks into contiguous admin slots, preserving larger uninterrupted daytime windows for `deep` blocks (using Focus Lab preferred hours when >= 5 sessions across 2+ hours exist).
3. **Rebuild Plan ("Day Changed"):**
   - Re-evaluates uncompleted blocks (`status: 'todo' | 'scheduled'`) around updated commitments, sleep/wake changes, or a "rebuild from now" cursor.
   - Preserves `done` and `skipped` blocks as-is; unplaceable blocks fall back to Today's To-Do or the Tray with explicit explanations.
4. **Shutdown Ritual:**
   - Guides the user through remaining unfinished blocks for the date (move to tomorrow, return to tray, or mark `skipped`), captures an optional `reflection`, and sets `DayPlanMeta.shutdownDone = true`.

## 6. Focus Lab Handoff & Planned-vs-Actual Reporting

- **Start Block in Focus Lab:**
  - Every `todo` or `scheduled` block provides `"Start block"`, routing to `/focus?blockId=<id>&subject=<encoded>&plannedMin=<plannedMin>` (preserving existing `/focus?subject=...&plannedMin=...` compatibility).
  - Completing the timer session in Focus Lab creates the `FocusSession` and, when `blockId` is present, updates the linked `Block` with `status: 'done'`, `actualMin`, `focusSessionId`, and `completedAt`.
- **Planned-vs-Actual Display:**
  - Summaries display plain, neutral counts and durations with sample sizes (`Planned 150m · Actual 135m · n = 3 blocks`), alongside deep / shallow / recovery minute totals.
